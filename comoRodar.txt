PONTO & VIRGULA PAPELARIA
Loja ficticia feita em Django para a aula de Desenvolvimento Web III.

Site publicado: https://papelaria-rphm.onrender.com

COMO RODAR NO COMPUTADOR (PowerShell, dentro da pasta papelaria)

python -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver

Depois abra http://127.0.0.1:8000/
No computador o banco e o SQLite (arquivo db.sqlite3, criado pelo migrate).

LOGIN DE ADMINISTRADOR
Crie seu próprio administrador com:
python manage.py createsuperuser

Não compartilhe senhas nem coloque credenciais no repositório.

BANCO DE DADOS EM PRODUCAO
No Render o site usa o PostgreSQL do Supabase. A conexao fica na variavel
DATABASE_URL (Session Pooler, porta 5432, SSL), configurada no painel do Render.
Sem DATABASE_URL o site nao sobe em producao.
As imagens enviadas pelo site ficam guardadas no proprio banco.

TESTES
python manage.py test

SERVICOS
/gerenciar/servicos/    CRUD, filtros e indicadores dos serviços (só equipe)

PERSISTENCIA
Reiniciar o Render não deve recriar o banco: produtos, pedidos, usuários,
contatos, integrantes e imagens permanecem no PostgreSQL do Supabase.
Não use flush ou apague o banco para reiniciar a aplicação.
Os testes usam SQLite isolado mesmo que DATABASE_URL esteja configurada.

NAVEGACAO FINAL
O menu publico tem Quem Somos, Produtos, Contato e Entrar. A marca abre a Home.
Com login, Entrar e substituido por Dashboard e Sair. A equipe publica aparece
em Quem Somos. As rotas antigas /equipe/ e /servicos/ continuam funcionando,
mas nao fazem parte do menu. O CRUD de produtos e acessivel pela area de
servicos ou pelo Django Admin. Auto-Deploy do Render deve acompanhar master.
Antes de reiniciar, confirme a existencia de backup recuperavel do Supabase.
Nao faca deploy manual se o automatico estiver funcionando.
